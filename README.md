# Лаба 1. ER-модель: бібліотека

## Домен
Міська бібліотека: читачі беруть у тимчасове користування фізичні примірники книг.

**Чому цей домен:** він містить усі три типи зв'язків, які потрібно показати в роботі:
1. 1:N (видавець → книги, книга → примірники, читач → видачі);
2. «чистий» M:N без власних атрибутів (книга ↔ автор, книга ↔ категорія);
3. зв'язок із власними атрибутами (читач + примірник → **Видача**: дати, повернення) — єдина асоціативна сутність.

## Структура репозиторію

| Файл / Папка | Призначення |
| --- | --- |
| `spec.md` | сутності, атрибути, зв'язки словами + критерії прийняття |
| `model.mmd` | ER-модель (Mermaid `erDiagram`) — джерело істини |
| `er.md` | сторінка з рендером діаграми (GitHub малює Mermaid сам) |
| `AUDIT.md` | аудит моделі проти spec, топ-3 виправлення |
| `DEFENSE.md` | захист: чому домен і нормалізація, перевірка |
| `ai/` | збережені відповіді ШІ (генерація, аудит) та мої фідбеки |
| `adr/` | архітектурні рішення (Architecture Decision Records) |
| `prompts/` | промти до ШІ, яким згенеровано модель |
| `scripts/check_consistency.py` | перевірка збігу назв полів spec ↔ модель |

## Як відрендерити
- **На GitHub:** рендер ER-моделі можна переглянути безпосередньо у файлі [er.md](er.md) (GitHub малює Mermaid автоматично).
- **Локально:** `npx -p @mermaid-js/mermaid-cli mmdc -i model.mmd -o er.svg`
- **Онлайн:** вставити вміст `model.mmd` на [https://mermaid.live](https://mermaid.live)

## Процес
`spec.md` → промт ШІ (`prompts/01-generate-model.md`) → `model.mmd` → аудит → зміни **лише в spec/критеріях** → перегенерація моделі. Діаграму руками не правимо.
